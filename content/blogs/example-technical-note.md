一份技术笔记不需要记录所有细节。它首先要回答：这段代码解决什么问题，下次使用时需要注意什么？

下面用一个“合并标签”的小例子，演示如何组织说明。

## 明确输入与输出

假设输入是两组标签，希望去掉重复项，并保留第一次出现的顺序。

```python
def merge_tags(first: list[str], second: list[str]) -> list[str]:
    result = []
    seen = set()
    for tag in first + second:
        if tag not in seen:
            result.append(tag)
            seen.add(tag)
    return result

tags = merge_tags(["Python", "笔记"], ["笔记", "项目"])
# ["Python", "笔记", "项目"]
```

`seen` 用于判断标签是否出现过，`result` 用于保留顺序。变量各自承担一个职责，之后再看时更容易理解。

## 说明容易忽略的边界

| 输入情况 | 本例的处理方式 |
| --- | --- |
| 两组都是空列表 | 返回空列表 |
| 标签重复出现 | 保留第一次出现的位置 |
| 大小写不同 | 视为不同标签 |
| 带有多余空格 | 不主动去除空格 |

如果实际需求要把 `Python` 和 `python` 看作相同标签，就需要先确定大小写规范。不要让一个看似方便的处理悄悄改变业务含义。

## 记录原因，而不只是动作

有用的注释应该解释“为什么”，例如为什么保留输入顺序、为什么不在这里清理空格。

> 代码可以告诉读者程序做了什么；说明应该帮助读者理解为什么这样做。

## 留一个最小示例

一份可复用的笔记，最好包含：

1. 一句话的问题描述。
2. 一段能独立阅读的核心代码。
3. 预期输出与边界情况。
4. 下一次修改时需要重新考虑的假设。

不必追求篇幅。让未来的自己能快速恢复上下文，就是一份好笔记的价值。
